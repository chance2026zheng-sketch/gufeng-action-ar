# 古风动作 AR 网页

四个 Q 版古风动作（纺织、击鼓、祈福、书写）的 AR 展示页。手机扫码后用摄像头扫描对应的手绘原图，动作视频会贴附在图上；移动手机时视频跟随原图在真实空间中移动。

全部资源均为本地文件，不依赖任何外部 CDN。

## 一、部署到免费静态托管

手机调摄像头**必须是 HTTPS 地址**，本地文件直接扫码打不开摄像头。下面三种方式都免费、都自带 HTTPS。

### 方式 A：GitHub Pages（推荐）

1. 在 GitHub 新建一个仓库（Public 或 Private 均可，Pages 免费版需 Public）。
2. 把本文件夹里的 `index.html`、`ar.html`、`.nojekyll`、`assets/` 整个目录上传到仓库根目录（网页端可直接拖拽上传）。
3. 仓库 `Settings` → `Pages` → `Source` 选 `Deploy from a branch`，Branch 选 `main` / `/ (root)`，保存。
4. 等待约 1 分钟，访问地址形如：
   ```
   https://<你的用户名>.github.io/<仓库名>/
   ```

> `.nojekyll` 必须一起上传，否则 GitHub 会用 Jekyll 处理文件，可能导致 `assets/` 下部分文件 404。

### 方式 B：Netlify Drop（最快，无需命令行）

1. 打开 https://app.netlify.com/drop
2. 把 `index.html`、`ar.html`、`.nojekyll`、`assets/` 一起拖进去。
3. 立即得到一个 `https://xxx.netlify.app` 地址。

### 方式 C：Vercel

1. 把整个文件夹推送到 GitHub 仓库，或在 https://vercel.com 直接上传。
2. 框架预设选 `Other`，构建命令留空，输出目录填 `.`。
3. 得到 `https://xxx.vercel.app` 地址。

**托管限制**：本站总大小约 15 MB（视频 8.6 MB + 库 3 MB + 特征文件 1.6 MB + 图片 1.4 MB），最大单文件 2.9 MB。GitHub Pages 免费额度为单仓库 1 GB、月流量 100 GB，Netlify 免费版月流量 100 GB，均足够使用。

## 二、生成二维码

部署完成拿到 HTTPS 地址后：

1. 打开该地址，滚动到「生成本站二维码」区域。
2. 地址栏已自动预填当前站点地址，确认无误后点「生成二维码」。
3. 点「下载二维码」保存 PNG，即可打印张贴。

也可以点「用当前地址」重新填入。地址必须以 `https://` 开头，否则页面会提示且不生成二维码（因为 http 下手机无法调摄像头）。

## 三、使用方法

### 扫码模式（主推）

1. 手机扫二维码打开页面，点选一个动作。
2. 点「开启摄像头」，iOS 会额外弹窗请求传感器权限，请允许。
3. 把镜头对准**对应手绘原图**（页面下方「扫描参考图」区域可查看四张图，可打印或在另一块屏幕上全屏显示）。
4. 识别成功后视频贴附在图上，移动手机时视频跟随。
5. 丢失目标时会提示「已丢失原图」，重新对准即可。

四张图各自独立，扫哪张出哪个动作。入口页的四个按钮分别对应四张图，也可以直接带参数访问：

```
ar.html?action=fangzhi   纺织
ar.html?action=jigu      击鼓
ar.html?action=qifu      祈福
ar.html?action=shuxie    书写
```

### 陀螺仪兜底模式

手绘线条的特征点比照片少，识别成功率受光线、角度、打印质量影响较大。若扫图始终不成功，在 AR 页面点右上角「切换兜底模式」：

- 摄像头实景中悬浮播放该动作视频；
- 转动手机时视频随视角移动（依赖陀螺仪）；
- 不依赖图像识别，一定能看到效果，但视频不会精确贴附在图上。

也可以直接带 `&mode=gyro` 访问。

## 四、已知限制（如实说明）

1. **识别率**：四张手绘图提取到的特征点为 204–292 个，低于照片类素材（通常上千）。这决定了识别成功但对光照、倾斜角度、图像清晰度比较敏感。建议光线充足、图面正对镜头、距离 20–40 cm。已内置陀螺仪兜底模式应对识别失败。
2. **iOS 权限**：Safari 需要用户手势后才能启动摄像头，因此进入页面必须先点一次「开启摄像头」，这是系统限制，无法绕过。
3. **传感器权限**：iOS 13+ 需单独授权陀螺仪，弹窗时请允许；拒绝后 AR 追踪仍可工作，但兜底模式的视角随动会退化为视频居中播放。
4. **不支持自动横竖屏比例校正**：竖版手持即可，画面按 `object-fit: cover` 填充。

## 五、目录结构

```
index.html                     入口页：四个动作入口 + 参考图 + 二维码生成
ar.html                        AR 页：扫图追踪 + 陀螺仪兜底双模式
.nojekyll                      GitHub Pages 必需
assets/
  actions.js                   四个动作的配置（路径、比例、文案）
  img/    *.png                四张手绘图（页面缩略图与参考图）
  video/  *.mp4                四段动作视频
  targets/*.mind               图像追踪特征文件（本地编译产出）
  lib/
    aframe-v1.5.0.min.js       三维渲染
    mindar-image-aframe.prod.js  图像追踪运行时
    qrcode.bundle.min.js       二维码生成
```

## 六、修改与重新生成

- **改文案或换视频**：编辑 `assets/actions.js`，视频文件同名替换即可。
- **换了原图后重新生成特征文件**：需重新编译 `.mind`。编译脚本在开发目录（不随发布包提供），依赖 Node 与 `mind-ar`、`pngjs`。图片须先压平透明底为白色再编译，否则透明区域会干扰特征提取。
- **调整视频叠加大小**：MindAR 锚点内 1 单位 = 图片宽度，原点在图片中心。`actions.js` 里的 `planeHeight` 已按追踪图高宽比算好，改动时保持 `width: 1`、`height: 高/宽`。
